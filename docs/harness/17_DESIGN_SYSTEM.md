# 17 — DESIGN SYSTEM / VISUAL CONTRACT

## Brand direction
Sober, serious, musical, contemporary. Core palette direction: white/black/red. Avoid theatrical excess, gold-heavy ornamentation and generic “edtech rainbow”. Red is a signal/accent, not a permanent background.

## Tokens
Semantic tokens only: background, surface, elevated, text, muted, border, accent, accent-hover, success, warning, danger, focus. Exact hex values are a design decision to be recorded separately; do not hardcode colors throughout components.

## Typography
Readable UI sans-serif; optional display face only where it improves hierarchy. Music notation uses dedicated notation fonts/renderer.

## Components
AppShell, TopNav, SideNav, MobileNav, Breadcrumbs, PageHeader, Tabs, SegmentedControl, Button, IconButton, Input, Select, Search, FilterBar, Table, List, Card only when semantically appropriate, Modal, Drawer, Toast, Banner, Progress, Badge, Credential, Avatar, MediaPlayer, AudioTransport, ScoreCanvas, Timeline, Track, MixerChannel, Meter, Editor, EmptyState, ErrorState, Skeleton, Tooltip.

## UX principles
Information density appropriate to task; tool-first screens for Studio; reading-first for Academy; practice-first for Skill Builder; identity-first for Profile; community-first for Community; operations-first for Teacher/Admin.

## Kids
Same design language but larger targets, simpler hierarchy, clearer feedback, fewer simultaneous controls. No visual chaos.

## Do not
Do not add decorative gradients, giant hero blocks, fake statistics, arbitrary badges, excessive rounded cards, duplicated navigation or dark patterns.
